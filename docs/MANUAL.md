# machine-bootstrap: the complete manual for moving Giovanni's setup to a new computer

**Who this is for.** Giovanni, and any AI assistant (Claude, Codex or another) helping them. It assumes you remember
nothing about how this was built. Read it top to bottom once; afterwards use the table of contents.
**Last verified against the code:** 2026-10-25 (tool version = the git state of this folder).
**Short version:** `docs/RESTORE.md` is the one-page checklist. This file is the long version with the reasons,
the exact outputs, the failure cases and the recovery plans.

**Placeholders.** Anything written between `<` and `>` (for example `<newest file>`) is a placeholder: replace it, brackets
included, with the real value. Typed literally, the shell reads `<` and `>` as redirection and fails with
`syntax error near unexpected token`. Today's archive, ready to paste:

```bash
gpg --decrypt /run/media/yuji/0a34cf43-b7a8-4198-bb85-690e4c0149c4/machine-bootstrap/secrets/mb-secrets-20261026-081552.tar.gpg | tar -t | head
```

## 1. Rules for an AI assistant (read this first)

If you are an AI helping with this task, these rules override your defaults.

1. **Never ask for, accept, guess, store or log the passphrase.** Giovanni types it themself at a hidden prompt
   (`getpass`). If Giovanni pastes it into the chat, tell them to change it later with a new `secrets-backup`.
   Do not run `secrets-backup` or `secrets-restore` with input you generated; they need an interactive terminal where
   Giovanni types. Suggest they type `! python3 -m mb secrets-restore FILE` in the prompt so the output lands in the session.
2. **Never read, print or `cat` secret files**: `~/.ssh`, `~/.gnupg`, `~/.config/rclone`, `~/.config/gh/hosts.yml`,
   `~/.claude.json`, `~/.claude/.credentials.json`, `~/.codex/auth.json`, `~/.android/*.jks`, `*.properties`, `~/.config/wiki/*.env`,
   keyrings, kwallet. To check that one exists use `ls -l` or `test -f`; to check that a key works use `ssh -T git@github.com`.
3. **Dry run before `--apply`, always.** `restore` without `--apply` changes nothing (it may install the six prerequisites
   through `bootstrap.sh`). Show Giovanni the `[todo]` list and let them approve before applying.
4. **Keys before restore.** Order is fixed: get the tool, restore the keys (`secrets-restore`), then `restore --apply`,
   then personal files. The restore clones private repositories over SSH; without the key restored they fail.
5. **Never touch the boot loader, partitions or disks.** The tool deliberately skips `grub*`, `shim*`, `efibootmgr`, `mokutil`.
   Do not install them by hand "to fix" a missing package.
6. **Never write to the SSD outside `machine-bootstrap/`.** The rest of the drive holds Giovanni's other documents.
   Never run `rsync --delete` against the SSD or against the home folder.
7. **Never format, delete or overwrite** the old computer or the SSD until section 4 is fully ticked **and** the new
   computer has passed section 5's checks. The old disk is the only complete copy until then.
8. **Do not "fix" a failure by editing `state/` by hand.** `state/` is generated by `capture`. Fix the cause (usually a
   recipe in `mb.toml`) and re-run. Re-running is safe.
9. **Explain in plain language** and define each technical term the first time (Giovanni's standing preference).
10. **Report with proof.** End with what was run and what could not be checked.
11. **Outward-facing actions need Giovanni's approval:** pushing to GitHub, uploading to Google Drive, publishing the wiki.
12. Replies in the language Giovanni writes in (English or Portuguese); use they/them for Giovanni.

## 2. Words used in this manual

| Word | Meaning |
|---|---|
| **mb** | The command of this tool: `python3 -m mb <command>`, run from the project folder. Short for machine-bootstrap. |
| **state/** | A generated folder in the project: the "photo" of the old computer (package lists, settings copies, repository addresses). Contains no secrets. |
| **Dry run** | Running a command in a mode that only prints what it would do and changes nothing. `restore` is a dry run unless `--apply` is given. |
| **Passphrase** | A long password (12+ characters) chosen by Giovanni when running `secrets-backup`. It is the only key to the encrypted archive. It is stored nowhere on a computer. |
| **Archive** | One file named `mb-secrets-YYYYMMDD-HHMMSS.tar.gpg`: a tar (a bundle of files) encrypted with GnuPG (the standard encryption program) using AES-256. Holds the keys and logins. |
| **SSD** | The external drive, filesystem btrfs, identified by its UUID (a unique id) `0a34cf43-b7a8-4198-bb85-690e4c0149c4`. On Linux it appears under `/run/media/<user>/`. |
| **apt / snap / flatpak** | Three ways Ubuntu installs programs. `apt` is the main one. |
| **Recipe** | A block in `mb.toml` that installs a program that is not an apt package (for example Node, Claude Code, the Android SDK). It has a `check` command (exit code 0 = already installed) and an `install` command. |
| **Profile** | `same` (a reinstall of this Acer Nitro) or `new` (a different computer). `new` skips drivers, kernels and files tied to this laptop's hardware. |
| **`.mb-bak-DATE`** | The suffix added to a file the tool had to move aside before writing the saved version. Nothing is overwritten silently. |
| **Idempotent** | Safe to run again: steps already finished are skipped (`[done]`). |
| **Linger** | A systemd setting that lets Giovanni's background services run without being logged in. |
| **rclone** | The program that talks to Google Drive. Its remote is called `gdrive:`. |
| **rsync** | The program that copies folders and only transfers what changed. |

## 4. Before the old computer is wiped (checklist)

Do all of this on the old laptop. **Do not wipe anything until every box is ticked.** (For a brand-new computer where the old
one stays alive, still do 4.1 to 4.8: it is cheap and gives a fresh copy.)

### 4.1 Refresh the record
```bash
cd ~/dev/machine-bootstrap
python3 -m mb status        # lists differences between the machine and state/
python3 -m mb capture       # rewrites state/; refuses and names any file the secret scanner flags
python3 -m mb scan          # must say clean
```
Expected: exit 0. Exit 1 means a file was refused or a repository in `~/dev` has no remote ("NOT SAFE: no git remote"); the message names it. Anything else non-zero: read the message; a refused file is named, never printed.

### 4.2 Save the keys (only Giovanni can do this)
Plug in the SSD, make sure `rclone listremotes` shows `gdrive:`, then:
```bash
cd ~/dev/machine-bootstrap      # required: `python3 -m mb` only works from the project folder (else: "No module named mb")
python3 -m mb secrets-backup
```
- It asks `Passphrase:` and `Again:` (typed, hidden). Minimum 12 characters. Choose one you can write on paper.
- It writes `<SSD>/machine-bootstrap/secrets/mb-secrets-<date>.tar.gpg`, decrypts it again and compares every file
  with the original (`written and verified: ...`), then uploads to Drive and compares (`uploaded and compared: ...`).
- `not found, nothing saved for: X` means that path does not exist on this laptop (harmless if it never existed).
- `UPLOAD FAILED: gdrive:machine-bootstrap` means the SSD copy exists but Drive does not. See section 9 (rclone client id).
- **Write the passphrase on paper and keep it away from the laptop and the SSD.** Without it the archive is unrecoverable.
  This includes the QuizApp release signing key; losing it means the app can never be updated in place.
- Test that you remember it (changes nothing): `gpg --decrypt FULL_PATH_OF_THE_ARCHIVE | tar -t | head` (the real command is at the top of this manual) and type the passphrase;
  you should see a list of file names such as `.ssh/id_ed25519.pub`. (Printing names is fine; never print contents.)

### 4.3 Save the personal files
```bash
python3 -m mb data-backup --verify     # compares the SSD copy with the originals by checksum; no changes
python3 -m mb data-backup              # refreshes the copy (never deletes; keeps replaced versions under versions/)
python3 -m mb data-backup --bulk       # Anime, Videos, Games (about 259 GB): only if you want them; the SSD has about 900 GB free
python3 -m mb data-backup --verify     # again; must report no differences
```
It refuses to run if the SSD is not mounted or free space is too small.

### 4.4 Check what is NOT in git, and push it
The restore re-clones repositories from GitHub, so anything not pushed is lost.
```bash
cd ~/dev
for d in */; do d=${d%/}; [ -d "$d/.git" ] || { echo "$d: not a git repo (NOT backed up)"; continue; }
  echo "$d | remote: $(git -C $d remote get-url origin 2>/dev/null || echo NONE) | unpushed: $(git -C $d rev-list --count @{u}..HEAD 2>/dev/null || echo ?) | uncommitted files: $(git -C $d status --short | wc -l)"; done
```
On 2026-10-25 this showed (since then `machine-bootstrap` was pushed): `wiki` had many uncommitted files; `codex-skills` had uncommitted files;
folders such as `wiki-codex-pbar-docs`, `dl`, `android-sdk` are not git repositories (the SDK is re-downloaded by a recipe; check the others).
Commit and push what matters. Pushing is outward-facing: Giovanni decides, and decides public or private for new repositories.

### 4.5 Keep this project pushed (so step 5.1 works without the SSD)
It is a public repository, so `git clone` needs no login. Push every change (`git push`); main only accepts a commit whose CI check `gate` is green.
After pushing, add the `[github]` section in `pipeline-check.toml` and check that the CI run is green (see `CLAUDE.md`).

### 4.6 Things the tool cannot save: do these by hand
- **Chrome profile:** sign in to Chrome sync on the old machine and let it finish (bookmarks, passwords, extensions come back on sign-in).
- **Game installs and saves** (Steam, Lutris, Games folder): Steam cloud saves sync by themselves; for other games copy the save folders into a backed-up folder, or use `data-backup --bulk`.
- **Phone settings** (Android): not touched by this tool.
- **Tailscale:** the device name `yuji-nitro` is tied to the old machine; plan to log in again (6.2).
- **Anything installed outside apt/snap/flatpak/the recipes:** run `python3 -m mb status` to see what drifted; list manual installs in `~/Applications`, `/opt`, `~/.local/bin` yourself.
- **Hardware-specific:** monitor layout, printer, Bluetooth pairings.

### 4.7 Put a copy of this tool on the SSD
So that the tool is reachable even if GitHub is not (GitHub can be down or unreachable):
```bash
SSD=$(findmnt -n -o TARGET -S UUID=0a34cf43-b7a8-4198-bb85-690e4c0149c4)
mkdir -p "$SSD/machine-bootstrap/tool"
rsync -a --exclude build --exclude __pycache__ ~/dev/machine-bootstrap/ "$SSD/machine-bootstrap/tool/"
```
Repeat after every `capture`. It contains no secrets (the gate scans `state/`).

### 4.8 Final tick list
- [ ] `mb capture` done today, `mb scan` clean
- [ ] `mb secrets-backup` done **after the last change of any key or login**, "written and verified" and "uploaded and compared" both seen
- [ ] passphrase on paper, in a place that survives the laptop
- [ ] `mb data-backup --verify` reports no differences
- [ ] every repository pushed (4.4) and this project pushed to GitHub and copied to the SSD (4.7)
- [ ] this manual copied to the SSD (it travels inside `tool/docs/MANUAL.md`) and, if you want, printed
- [ ] the list in 4.6 handled

## 5. On the new computer, step by step

Each step says what to type, what you should see and what to do if you do not see it. Stop at the first surprise.

### 5.0 Install the operating system
Install Kubuntu/Ubuntu (the version tested is Ubuntu 26.04 LTS; same-or-newer is fine) with a user account that has `sudo`.
Use the **same username (`yuji`)** if you can: the saved files assume `/home/yuji` and the SSD mount path contains the user name.
Let the installer do the partitions and the boot loader; the tool never touches them. Connect to the internet. Do the system updates when prompted, then reboot.

### 5.1 Get the tool
Pick whichever works.

**A. From GitHub (public, or after you have the key):**
```bash
sudo apt-get update && sudo apt-get install -y git
git clone https://github.com/yujideluca/machine-bootstrap ~/dev/machine-bootstrap
cd ~/dev/machine-bootstrap
```
Expected: the folder contains `bootstrap.sh`, `mb/`, `mb.toml`, `state/`. If the repository is private you get "Repository not found": use B.

**B. From the SSD:**
```bash
lsblk -f                                   # find the SSD: look for UUID 0a34cf43-b7a8-4198-bb85-690e4c0149c4
ls /run/media/$USER/                       # KDE normally mounts it here when plugged in; if not, click it in Dolphin's sidebar
SSD=/run/media/$USER/0a34cf43-b7a8-4198-bb85-690e4c0149c4
mkdir -p ~/dev && rsync -a "$SSD/machine-bootstrap/tool/" ~/dev/machine-bootstrap/
cd ~/dev/machine-bootstrap && chmod +x bootstrap.sh
```
(If the mount folder has another name, use the one `ls` shows. If `lsblk -f` shows no btrfs drive, check the cable and try another port.)

Check you have the tool: `python3 -m mb --help` prints the list of commands.

### 5.2 Restore the keys and logins FIRST
```bash
ls -l "$SSD/machine-bootstrap/secrets/"          # pick the newest mb-secrets-*.tar.gpg (the date is in the name)
python3 -m mb secrets-restore "$SSD/machine-bootstrap/secrets/<newest file>"
```
- Type the passphrase at `Passphrase:` (hidden). Expected last line: `restored N entries with owner-only permissions`.
- It **refuses** to overwrite existing files and lists them (`would overwrite existing files (use --force ...)`). On a fresh account that
  should not happen. If it does, look at the listed files; `--force` moves the existing ones to `name.mb-bak-DATE` first, then writes.
- A wrong passphrase gives a gpg decryption error and writes nothing. Retry. After several failures check the file is the right one and
  was not cut short (compare sizes with the Drive copy).
- No SSD? The same file is on Google Drive in `machine-bootstrap/`. Download it from `drive.google.com` in a browser (sign in as Giovanni), then pass the downloaded path.
- Permissions are set automatically: `~/.ssh` and `~/.gnupg` folders 700, files owner-only.

Verify, without printing any secret:
```bash
ssh -T git@github.com            # "Hi yujideluca! You've successfully authenticated" (first time it asks to trust github.com: answer yes)
gpg --list-secret-keys           # shows the key owners, not secrets
test -f ~/.android/german-quiz-release.jks && echo "release key present"
```

### 5.3 Dry run of the restore
```bash
./bootstrap.sh
```
`bootstrap.sh` first installs the six tools the restore itself needs if missing (git, python3, rclone, rsync, gnupg, curl; it asks for your sudo password),
then runs `python3 -m mb restore` as a **dry run**. You see one line per step:

| Mark | Meaning |
|---|---|
| `[done]` | already in the wanted state |
| `[todo]` | would be done by `--apply` (`(needs root)` = will use sudo) |
| `[FAIL]` | a step failed (only on `--apply`) |
| `apt package skipped on purpose (the installer owns it)` | a boot-loader package; correct, do not change |
| `apt package not available on this system, skipped: X` | the new Ubuntu has no such package; see 12 for the known ones |
| `not available yet, will be retried after the new apt sources are added` | normal on a dry run for packages from Chrome/Tailscale/ChatGPT repositories |

The last lines: `N done, M to do`, `Nothing was changed.`

Read the `[todo]` list with Giovanni. A dry run is cheap; repeat as often as you like.

### 5.4 Apply it
```bash
./bootstrap.sh --apply                    # reinstall of THIS laptop (profile "same")
./bootstrap.sh --apply --profile new      # a DIFFERENT computer
```
- It asks for the sudo password once, then runs unattended. Expect **30 to 90 minutes** (downloads; the proof run in the VM took about an hour).
- Order (see section 8): third-party apt sources and keys, `apt update`, apt install, flathub, snaps, flatpaks, `git clone` of every repository
  in `state/repos.txt`, the recipes (uv, Rust, cargo tools, Node, Elm tools, pyright, Claude Code, Codex, JDK, Gradle, Android SDK, `mem`, the wiki build),
  and **last** your settings files (a file that already exists and differs is first saved as `name.mb-bak-DATE`).
- It carries on after a failed step and reports it. To stop at the first failure add `--stop-on-error`.
- Close any window that shows it is waiting; do not interrupt. If it is interrupted, just run it again.
- It ends with `N done, M failed or pending`. Anything failed or pending: section 9, then run the same command again.
- Run it **a second time**. The second run must show everything `[done]` except what is documented as expected (private clones that need the key, packages "not available").

### 5.5 Log out and in (or reboot)
Needed so the restored KDE settings, shell setup, PATH and user services take effect:
```bash
systemctl --user daemon-reload
reboot
```

### 5.6 Personal files
With the SSD plugged in:
```bash
rsync -a --info=progress2 "$SSD/machine-bootstrap/home/" ~/
```
- This adds and updates files; it does **not** delete anything (no `--delete`).
- Add a dry run first if you want to see what would be copied: `rsync -an --itemize-changes "$SSD/machine-bootstrap/home/" ~/ | head`.
- Do not run it before step 5.4 finished: the restore writes settings and this copies documents; mixing them causes confusion.
- Large optional folders (Anime, Videos, Games) are only on the SSD if `data-backup --bulk` was run; they are copied by the same command.

### 5.7 Checks that it worked
| Check | Command | Expected |
|---|---|---|
| Record matches the machine | `cd ~/dev/machine-bootstrap && python3 -m mb status` | no differences, or only intended ones |
| Dry run | `python3 -m mb restore` | all `[done]` apart from documented exceptions |
| GitHub | `ssh -T git@github.com` and `gh auth status` | authenticated |
| Repositories | `ls ~/dev` | the 11 repositories in `state/repos.txt` (QuizApp, QuizWeb, codex-pbar, codex-skills, german-quiz-releases, pipeline-check, processing-sketches, project-template, remote-terminal, wiki, workflow-memory) |
| Tools | `uv --version; node --version; claude --version; codex --version; cargo --version; elm --version; java -version; gradle --version` | each prints a version; `elm` must be 0.19.1 |
| Android | `ls ~/dev/android-sdk/platform-tools` and `~/dev/android-sdk/cmdline-tools/latest/bin/sdkmanager --version` | exist |
| Memory tool | `mem --help` | works |

## 6. After the restore: what is still manual

### 6.1 Always
- Open Chrome and sign in (sync restores profile data).
- Verify the weekly timer exists (5.7). If missing: `python3 -m mb install-timer`.
- `python3 -m mb capture` on the new machine, review, commit, push: the record now describes the new machine (use `--profile same` semantics from now on).

### 6.2 Maybe (depends on what the old setup had)
These are expected consequences of the machine being new; they were not proven in the VM.
- **Tailscale:** run `sudo tailscale up` and sign in. The wiki's public address (Tailscale Funnel on `yuji-nitro.tailed3a22.ts.net`) depends on the machine name and Funnel being enabled again; check the wiki's own documentation page in `~/dev/wiki/content/`.
- **Different graphics card:** install the right driver (`ubuntu-drivers devices`, then `sudo ubuntu-drivers install`). With `--profile new` Nvidia packages were skipped on purpose.
- **Different keyboard or screens:** KDE settings restored from the old laptop may not fit (`kwinoutputconfig.json`, `kxkbrc`). Adjust in System Settings.
- **Games:** reinstall Steam/Lutris games; saves from backup or Steam cloud.
- **Phone:** re-pair for adb (the keys `~/.android/adbkey*` were restored, so the phone may trust the computer already).
- **Packages marked "not available":** install an alternative or skip.

## 7. Command reference

All commands run from `~/dev/machine-bootstrap` as `python3 -m mb <command>`. Exit code 0 = success.

| Command | What it does | Writes to | Notes |
|---|---|---|---|
| `capture` | Records the machine into `state/`: manual apt packages, snaps, flatpaks, repository addresses, an allow-listed set of settings and system files | `state/` | Refuses files the scanner flags (names them only). Exit 1 if a file was refused or a repository has no remote ("NOT SAFE"). |
| `status [--notify]` | Compares the machine with `state/` | nothing | Exit 1 when different. `--notify` also shows a desktop notification (used by the weekly timer). |
| `install-timer` | Installs `mb-status.service` and `mb-status.timer` (weekly) in `~/.config/systemd/user` | those two files | |
| `restore [--apply] [--profile same\|new] [--stop-on-error]` | Dry run by default. `--apply` installs everything per section 5.4 | the system | `same` is the default. Exit 1 if any step failed. |
| `secrets-backup [--to ssd\|gdrive\|FOLDER\|remote:path]` | Packs the files listed in `[secrets]` into an archive, encrypts, verifies, copies. Default `--to ssd --to gdrive` | SSD `machine-bootstrap/secrets/`, Drive `machine-bootstrap/` | Interactive passphrase. Minimum 12 characters. The archive filename carries the date. Older archives are kept, never overwritten. |
| `secrets-restore ARCHIVE [--force]` | Decrypts and writes the files back with owner-only permissions | your home folder | Refuses to overwrite unless `--force` (then the old file becomes `.mb-bak-DATE`). Rejects unsafe archive entries (absolute paths, `..`). |
| `data-backup [--to ssd\|PATH] [--bulk] [--verify]` | rsync of the personal folders to the SSD | SSD `machine-bootstrap/home/`, `versions/` | Never deletes. `--verify` is read-only. `--bulk` adds Anime, Videos, Games. |
| `scan` | Fails if `state/` holds anything that looks like a secret | nothing | Part of the quality gate. |
| `./bootstrap.sh [mb restore flags]` | Installs git, python3, rclone, rsync, gnupg, curl if missing, then runs `mb restore` | the six prerequisites | Never applies by itself. |

Configuration file: `mb.toml` (one place that decides everything captured, restored and backed up). Section 13 lists its contents.

## 8. How the restore works inside (for debugging)

For an AI that has to fix a failure. Source files are in `mb/`.

1. `cli.py:cmd_restore` builds a **plan** with `plan.build_plan(facts, config, state, profile)`. This reads the machine through a `Facts` object and `state/`
   and returns a list of `Step` objects (title, command, `root`, `done`). It changes nothing.
2. `plan.apply_plan` executes the steps in this order, using `plan.run_step`:
   1. third-party apt sources and keyrings copied from `state/etc/` (only those allowed by the profile);
   2. `apt-get update`;
   3. `sudo env DEBIAN_FRONTEND=noninteractive apt-get install -y <packages>` for the manual list minus `never_packages` (boot loader) and, on `--profile new`, minus `hardware_packages`;
   4. early recipes (`stage = "after-apt"`, flathub);
   5. snaps, flatpaks;
   6. `git clone` for each line in `state/repos.txt` that is missing;
   7. other recipes, in file order, each skipped when its `check` command exits 0;
   8. settings files from `state/home/` (a differing existing file is renamed `.mb-bak-DATE` first), then `systemctl --user daemon-reload`.
3. After step 1 the plan is built **a second time**, because packages from the new sources were invisible before.
4. Recipes run with `~/.local/bin` and `~/.cargo/bin` first on PATH (function `step_env`).
5. Why settings are last: installers (uv, rustup, Claude Code) append lines to `~/.bashrc` and `~/.profile`; writing the saved versions afterwards makes a second run find nothing changed.
6. Tests never touch the real system: `FakeFacts` plus a runner that fails the test if called. `tools/quality_gate.sh` is the only definition of "passing".
7. **Proof:** `tools/vm-test.sh` boots a clean Ubuntu 26.04 virtual machine (QEMU), runs `bootstrap.sh --apply --profile new` and checks 27 things with `tools/vm_assert.py`. On 2026-10-25 it passed (4th run). Evidence: `build/vm-proof/` (not in git). Rerun it after changing a recipe, `plan.py` or `bootstrap.sh`, and every few months, because download addresses change.

## 9. Troubleshooting table

| Symptom | Likely cause | What to do |
|---|---|---|
| `The backup drive (UUID ...) is not mounted` | SSD unplugged or not mounted | Plug it in; open it in Dolphin once; `findmnt -S UUID=0a34cf43-b7a8-4198-bb85-690e4c0149c4` must print a line. If the SSD was replaced by a new drive, set `ssd_uuid` in `mb.toml` to its UUID (`lsblk -f`). |
| `gpg: decryption failed: Bad session key` / `No data` | Wrong passphrase, or the file is damaged | Retype carefully (keyboard layout! the installer may use a different layout than the old laptop; test by typing the passphrase in a visible text box first). Try the other copy (Drive/SSD). |
| `would overwrite existing files` on `secrets-restore` | The account already has `.ssh`, `.gitconfig`... | Read the list. If it is only files you can lose, rerun with `--force`; the old ones become `.mb-bak-DATE`. |
| `Permission denied (publickey)` when cloning | Keys not restored yet, or the key is not on GitHub | Do 5.2 first. `ssh -T git@github.com`. If the key is correct but rejected, add the public key (`~/.ssh/id_*.pub`) to GitHub → Settings → SSH keys. |
| Clone of `codex-pbar` or `project-template` fails | They are private repositories | Same as above; after the key works, run `./bootstrap.sh --apply` again. |
| `E: Unable to locate package X` / `apt package not available ... skipped` | Package is gone in the new release | Expected for `vesktop`, `utility-birdid`, `umu-launcher-git-dummy-builddeps`, `claude-desktop` (see 12). Others: search `apt search`, install an alternative, remove from `state/apt-manual.txt` only through `capture`. |
| `[FAIL] recipe node` (or uv, claude-code, ...) with a curl error / 404 | A download address moved | Open the failing `[[recipe]]` in `mb.toml`, find the current download page of that program, change the URL/version, rerun. Then rerun `tools/vm-test.sh`. |
| `[FAIL] recipe wiki`: Elm version message | Wrong Elm version | `elm --version` must be 0.19.1. Reinstall with `npm install -g elm@0.19.1-6` (recipe `node-global-tools`). |
| `sdkmanager` license or Java errors | Java not found | The recipe sets `JAVA_HOME` from `~/dev/jdk-21*`. Check `ls -d ~/dev/jdk-21*`; rerun. |
| Second run still shows `[todo]` | Something changed between runs | Read which step. Settings files showing as todo after the recipes = an installer edited `.bashrc` again; rerun once more. |
| Restore finished but the desktop looks default | Settings take effect on next login | Log out and in (5.5). |
| `UPLOAD FAILED: gdrive:` | rclone's shared Google client id is retired (rclone warned it stops working during 2026), the token expired, or no internet | `rclone about gdrive:` to test. Create your own client id: https://rclone.org/drive/#making-your-own-client-id, then `rclone config reconnect gdrive:`. Meanwhile the SSD copy is valid. |
| `data-backup` says not enough free space | SSD too full | Free space or exclude `--bulk`. The tool checks before copying. |
| `Run again with --apply` message but nothing happened | You ran the dry run | Add `--apply`. |
| Boot-loader packages missing/odd | By design | Never install `grub-pc`/`grub-efi` by hand on top of the installer's choice; it can make the machine unbootable. |
| `mb status` says drift right after a restore | Normal: the new machine differs | `capture`, review, commit. |

If a failure is not here: copy the exact `[FAIL]` line and its output, read the step's command in `mb.toml` or `mb/plan.py`, fix the cause, rerun.
Rerunning is always safe.

## 10. Disaster scenarios

| Situation | What still works | What to do |
|---|---|---|
| **Forgot the passphrase** | Everything except the archive: packages, settings, repositories (public ones), personal files. | The archive cannot be opened (AES-256; there is no back door). Rebuild keys by hand: generate a new SSH key (`ssh-keygen -t ed25519`), add it to GitHub; `gh auth login`; log in to Claude (`claude`), Codex (`codex login`), rclone (`rclone config`), the wiki (new Google OAuth client). **The Android release key `german-quiz-release.jks` cannot be recreated:** an app signed with a new key cannot update the installed one in place. Whether a signing-key reset exists depends on how the app is distributed (not verified); find out now, before it matters. |
| **SSD broken or lost** | State in git; the archive on Drive; repositories on GitHub. | Get the archive from Drive (browser). Clone the tool from GitHub (needs the repo pushed). Personal files are lost unless another copy exists: this is why `data-backup` should be refreshed and the SSD itself duplicated if the files are irreplaceable. |
| **SSD and Drive copies both gone** | Everything except the keys. | As "forgot the passphrase". |
| **GitHub unavailable** | The tool copy on the SSD (`tool/`). | Use 5.1 B. Repositories cannot be cloned until GitHub is back; clone them later with `mb restore --apply` (clones what is missing). |
| **Google Drive unavailable** | The SSD archive. | Nothing to do now; re-upload later with `secrets-backup --to gdrive`. |
| **A restore went wrong halfway** | Replaced files exist as `name.mb-bak-DATE`. | Compare, put back what you want. Rerun `restore --apply`. |
| **The old laptop dies before section 4 was done** | Whatever the last backups hold, plus GitHub. | Follow section 5 with the last archive and `state/`. `state/` may be stale: after the restore, install what is missing by hand. This is why section 11 exists. |
| **The new computer is a different CPU architecture (ARM)** | Packages yes, recipes no | The recipes download x86_64 builds (Node, Gradle SDK pieces, JDK). Edit them for `aarch64` and re-test; not covered. |
| **The Ubuntu version is much newer** | Most of it | Expect some `not available` packages and some recipe URL changes; handle with section 9. |

## 11. Keeping the backup fresh

A backup that is a year old restores a year-old computer. The tool helps but cannot do it for Giovanni.

| When | What | Command |
|---|---|---|
| Weekly, automatic | A notification when the machine drifted from the record | the timer `mb-status.timer` (installed 2026-10-25; check with `systemctl --user list-timers mb-status.timer`) |
| After the notification, or monthly | Update the record, review the diff, commit and push | `python3 -m mb capture` |
| After changing any key, token, login or the Android key | New archive (the old one stays) | `python3 -m mb secrets-backup` |
| Monthly with the SSD plugged in | Refresh personal files | `python3 -m mb data-backup` then `--verify` |
| After changing a recipe or `plan.py` | Re-prove on a clean machine (about an hour, runs in the background) | `tools/vm-test.sh`; record the result in the decision log of `DESIGN.md` |
| Every few months | Make sure Drive still accepts uploads and that you can still open the newest archive | `rclone about gdrive:` and the test in 4.2 |
| After every capture | Copy the tool to the SSD | 4.7 |

A change to this tool follows the project's rules in `CLAUDE.md`: requirement, then test, then code; `tools/quality_gate.sh` must pass.

## 12. What is NOT covered or NOT proven

Honest list as of 2026-10-25.

**Proven** (VM, 27 checks, `tools/vm-test.sh`): the dry run and apply on a clean Ubuntu 26.04; 405 settings files identical to the record; second run idempotent;
public repositories cloned; Chrome and Tailscale installed from restored sources; uv, Node, Claude Code, Codex, Rust, Elm 0.19.1, pyright, JDK 21,
Gradle, Android SDK, wiki build; systemd units and linger; a secrets round trip with a test key; the unmounted-drive guard.

**Not proven**
- Cloning `codex-pbar` and `project-template` (private repositories): needs the real SSH key.
- The real archive with the real passphrase: needs Giovanni. `secrets-backup` was run on 2026-10-26 (`mb-secrets-20261026-081552.tar.gpg` on the SSD); whether it decrypts with the passphrase from a cold start has not been tested by an assistant. Test it (4.2).
- Restore onto physical hardware (a VM has no Nvidia card, no KDE session of yours, no real SSD).
- Starting the wiki service and the public Tailscale address on a new machine.
- Rebuilding the wiki and its public address after the machine name changes.

**Not covered**
- Browser profiles (Chrome sync does it), game installs, the phone's own settings, Bluetooth/printer pairings.
- Repositories or folders that are not on GitHub: `wiki-codex-pbar-docs`, `dl`, uncommitted work anywhere (4.4).
- Packages that exist only on this laptop: `vesktop`, `utility-birdid`, `umu-launcher-git-dummy-builddeps`, `claude-desktop` (skipped with a message).
- `openssh-server` is in the manual list and will be installed; if you do not want a server on the new machine, remove it afterwards (`sudo apt-get remove openssh-server`) and do not re-capture it.
- ARM computers.

**Known risks**
- The rclone Google Drive remote used a shared client id that rclone said stops working during 2026. A personal Google OAuth application (the identity rclone uses to talk to Drive) has since been set up; `docs/PRIVACY.md` is its privacy notice. I have not tested an upload with it, and I did not read the rclone configuration (it is secret). Test with `rclone about gdrive:`.
- Recipe download addresses rot; only the VM test finds this.
- The passphrase lives only in Giovanni's memory and on paper.
